**Перечень допустимых лексем:**

- Ключевые слова: `const`, `var`, `struct`, `enum`, `union`, `fn`, `pub`, `return`, `if`, `else`, `while`, `for`, `break`, `continue`.
- Встроенные типы: `u8`, `u16`, `u32`, `u64`, `i8`, `i16`, `i32`, `i64`, `f16`, `f32`, `f64`, `bool`, `void`, `usize`, `isize`.
- Идентификаторы: последовательности латинских букв, цифр и `_`, начинающиеся с буквы или `_`.
- Числа: целые (`123`) и вещественные (`3.14`).
- Операторы: `+`, `-`, `*`, `/`, `%`, `=`, `<`, `>`, `!`, `&`, `|`, `^`, `~`, `?`, а также двухсимвольные: `==`, `!=`, `<=`, `>=`, `=>`, `->`, `<<`, `>>`, `++`, `--`.
- Разделители:`{`, `}`, `(`, `)`, `[`, `]`, `,`, `;`, `:`, `.`.
- Комментарии: однострочные `// ...` (пропускаются).

Все остальные символы считаются недопустимыми и выводятся как ошибки с указанием строки и позиции.

![диаграмма состояний](state_diagram.png)

- S (начальное состояние) — пропускает пробельные символы, определяет тип лексемы по первому символу и передаёт управление соответствующему состоянию.
- ID — читает последовательность латинских букв, цифр и `_`. По завершении проверяет, является ли полученное слово ключевым, встроенным типом или идентификатором.
- NUM — читает целую часть числа, при наличии `.` — дробную часть.
- PUNCT — одиночный знак пунктуации.
- OP — оператор (возможно двухсимвольный, например `==` или `->`).
- SKIP — пропускает пробелы, табуляции, переводы строк и однострочные комментарии.
- EMIT — добавляет готовую лексему в результирующий список и возвращает управление в S.

буква (A–Z, a–z) или _	         ID
цифра (0–9)	                     NUM
+ - * / % = < > ! & | ^ ~ ?	     OP
{ } ( ) [ ] , ; : .	             PUNCT
пробел, \t, \n, \r	             SKIP
/ + /	                         SKIP (пропустить до конца строки)
всё остальное	                 ERROR (или сразу EMIT с типом Unknown)

**Внутренние переходы:**
ID → ID: пока символ — буква, цифра или _.
NUM → NUM: пока символ — цифра.
NUM → NUM: если символ . и следующий — цифра.
ID → EMIT: как только символ не подходит.
NUM → EMIT: как только символ не цифра.
OP → EMIT: сразу (1 или 2 символа).
PUNCT → EMIT: сразу (1 символ).
SKIP → SKIP: пока пробел или \n.
SKIP → S: как только встретился непробельный символ.
EMIT → S: всегда.

### Разработка грамматики
Для описания синтаксической конструкции «объявление структуры на языке Zig» разработана следующая грамматика G[Z]:

Z        → Decl
         | Z Decl

Decl     → 'const' Ident '=' 'struct' '{' Fields '}' ';'
         | 'const' Ident '=' 'struct' '{' '}' ';'

Fields   → Field
         | Fields ',' Field
         | Fields ','

Field    → Ident ':' Type

Type     → '[' ']' 'const' Type
         | Ident

Обозначения:

Z — начальный символ (программа из одного и более объявлений структур);
Decl — одно объявление структуры;
Fields — список полей, разделённых запятыми; допускается запятая перед закрывающей фигурной скобкой;
Field — одно поле вида имя : тип;
Type — либо срез []const <Type>, либо идентификатор (встроенный тип или пользовательский);
Ident — идентификатор (в позиции имени допускаются также ключевые слова и встроенные типы, кроме зарезервированных const и struct).

Грамматика допускает:

пустую структуру struct {} — правило с пустым списком полей;
несколько объявлений подряд — правило Z → Z Decl;
запятую перед } — правило Fields → Fields ',';
вложенные срезы, например []const []const u8.

### Классификация грамматики по Хомскому
Разработанная грамматика относится к контекстно-свободным грамматикам (тип 2 по классификации Хомского).

Обоснование:

в каждой продукции слева стоит ровно один нетерминальный символ;
правая часть содержит произвольную цепочку из терминалов и нетерминалов;
ни одно правило не имеет вида αAβ → αγβ с непустым контекстом (это было бы контекстно-зависимой грамматикой, тип 1);
ни одно правило не содержит двух и более нетерминалов в левой части (это было бы грамматикой типа 0);
грамматика не является автоматной (тип 3), так как в правилах для Decl, Fields, Field, Type правая часть содержит больше одного символа и присутствует вложенность — значит, это строго контекстно-свободная грамматика.

### Метод анализа
Для разбора выбран метод рекурсивного спуска (LL(1)-подобный). Для каждого нетерминала реализована отдельная процедура, которая:

проверяет текущий токен;
при совпадении переходит к следующему;
при несовпадении фиксирует ошибку и передаёт управление механизму синхронизации.

Схема метода анализа:

![метод анализа](metod_diagram.png)

Если текущий токен совпадает с ожидаемым значением — переходим к следующему, иначе — фиксируем ошибку с указанием позиции и не двигаемся дальше (синхронизацию выполняет внешний уровень). Кнопка «Пуск» запускает сначала лексический анализатор, затем — синтаксический. Если на лексическом этапе обнаружены ошибки, синтаксический анализ не выполняется, поскольку токенизация некорректна.

### Диагностика и нейтрализация синтаксических ошибок
Для нейтрализации ошибок применён метод Айронса. Идея метода: при обнаружении ошибки анализ не прекращается — выполняется пропуск токенов до ближайшего синхронизирующего токена из множества follow текущего нетерминала. После синхронизации разбор продолжается с того места, где встретился синхронизирующий токен.

Множества синхронизирующих токенов для нетерминалов грамматики:

| Нетерминал | Синхронизирующие токены |
|---|---|
| `Z` | `const`, конец файла |
| `Decl` | `const`, `;`, конец файла |
| `Fields` | `,`, `}`, `;`, конец файла |
| `Field` | `,`, `}`, `;`, конец файла |
| `Type` | `,`, `}`, `;`, конец файла |
Алгоритм:

При несовпадении текущего токена с ожидаемым фиксируется ошибка с указанием фрагмента, строки и позиции.
Вызывается процедура синхронизации SkipTo<Sync>, которая пропускает токены до ближайшего синхронизирующего.
Разбор продолжается с этого токена.

Такая стратегия позволяет обнаружить несколько ошибок за один проход и не останавливаться на первой. Все ошибки собираются в список и выводятся в таблицу результатов. Ошибочные строки в таблице подсвечиваются оранжевым цветом. При клике по строке с ошибкой курсор в области редактирования перемещается к позиции ошибочного фрагмента.

Пример работы метода Айронса для строки:

const Person = struct { name u8, age: u8, };

Обнаруживаются две ошибки:
пропущен символ : после имени name;
пропущен символ , между полями name u8 и age: u8.

Разбор не останавливается после первой ошибки — обе фиксируются за один проход.

Вход: текст, введённый пользователем в область редактирования.
Выход: таблица найденных подстрок с указанием позиций, длины и количества совпадений; подсветка соответствующих фрагментов в исходном тексте.

### Вариант задания
Номер варианта: 15.
Три задачи на поиск подстрок:
Найти все целые числа без знака.
Найти все шестнадцатеричные литералы Zig (вида 0x...).
Найти все идентификаторы, начинающиеся с заглавной буквы.

### Решение 3 задач

Задача 1. Целые числа без знака
Описание задачи. Требуется найти в тексте все последовательности цифр, представляющие целые неотрицательные числа. Число не должно содержать знака (+ или -) и не должно быть частью другого слова или числа с плавающей точкой.
\b\d+\b
Пояснение обозначений:
\b — граница слова (позиция между словесным и несловесным символом). Гарантирует, что число не является частью более длинного слова.
\d — любая цифра от 0 до 9.
+ — квантификатор «одно и более повторений». Означает, что число состоит минимум из одной цифры.
\b — закрывающая граница слова. 

Примеры строк, которые должны находиться:

42;0;2024;const Value = 100;

Примеры строк, которые не должны находиться:
.5 — нет цифры перед точкой;3.14 — число с плавающей точкой, а не целое;abc123def — цифры внутри идентификатора, не отдельное число;-7 — знак минус, а по условию число без знака.
![Пример 5](Primer5.png)

Задача 2. Шестнадцатеричные литералы Zig
Описание задачи. Требуется найти в тексте все шестнадцатеричные литералы, записанные в синтаксисе языка Zig. Литерал начинается с префикса 0x или 0X, за которым следует одна или более шестнадцатеричных цифр (0–9, a–f, A–F).
\b0[xX][0-9a-fA-F]+\b
Пояснение обозначений:
\b — граница слова;
0 — обязательный символ нуля;
[xX] — класс символов: либо строчная x, либо заглавная X;
[0-9a-fA-F] — класс шестнадцатеричных цифр: цифры 0–9, латинские буквы a–f в обоих регистрах;
+ — квантификатор «одно и более повторений»;
\b — закрывающая граница слова.

Примеры строк, которые должны находиться:
0xFF;0x1a2b;0XABCD;const mask = 0xFF00;

Примеры строк, которые не должны находиться:
0x — нет ни одной шестнадцатеричной цифры после префикса;
xFF — нет обязательного префикса 0x;
0xGG — G не является шестнадцатеричной цифрой;
42 — десятичное число, не hex-литерал.
![Пример 6](Primer6.png)

Задача 3. Идентификаторы, начинающиеся с заглавной буквы
Описание задачи. Требуется найти в тексте все идентификаторы, которые начинаются с заглавной латинской буквы. Идентификатор — это последовательность латинских букв, цифр и символа подчёркивания, начинающаяся с буквы.
\b[A-Z][A-Za-z0-9_]*\b
Пояснение обозначений:
\b — граница слова;
[A-Z] — одна заглавная латинская буква (первый символ идентификатора);
[A-Za-z0-9_] — класс символов: заглавные и строчные латинские буквы, цифры и подчёркивание;
* — квантификатор «ноль и более повторений»;
\b — закрывающая граница слова.
* 
Примеры строк, которые должны находиться:
Person;Config;MyStruct_1;const Person = struct { ... };

Примеры строк, которые не должны находиться:
person — начинается со строчной буквы;
_Config — начинается с подчёркивания;
1Person — начинается с цифры;
имя — кириллица, а не латиница.

### Ограничения
Поиск выполняется только по одному шаблону за раз — задача выбирается в выпадающем списке.
Регулярные выражения не учитывают контекст — например, первая задача найдёт 0 внутри 0xFF как отдельное число.
Поиск выполняется по всему тексту редактора, без учёта регистра — регистр важен только внутри шаблонов.
Поддерживаются только три задачи, заданные вариантом; добавление новых требует изменения кода.
Регулярные выражения используют стандартный синтаксис .NET (System.Text.RegularExpressions).

# Лабораторная работа 5. Построение AST и проверка контекстно-зависимых условий
### Вариант задания
15- объявление структуры на языке Zig.
Примеры корректных строк:
1)
const Person = struct {
    name: []const u8,
    age: u8,
};
2)
const Point = struct {
    x: i32,
    y: i32,
};
3)
const Config = struct {
    host: []const u8,
    port: u16,
    enabled: bool = true,
};

### Контекстно-зависимые условия
Правило 1. Уникальность идентификаторов
Проверяется, что имя структуры не объявлено ранее в той же области видимости, а также что имена полей внутри одной структуры уникальны. При обнаружении дубликата ошибка выводится, символ повторно в таблицу не добавляется.
Пример:
const Person = struct {
    age: u8,
};
const Person = struct {
    name: []const u8,
};

Правило 2. Совместимость типов
Проверяется, что тип значения по умолчанию соответствует типу поля. Если поле имеет тип bool, а значение — число, или наоборот, фиксируется ошибка. Аналогично для числовых типов, если значение не является числом.
Пример:
const Person = struct {
    active: bool = 5,
};

Правило 3. Допустимые значения
Проверяется, что числовое значение по умолчанию входит в диапазон своего типа. Если значение вне диапазона, фиксируется ошибка с указанием границ.
Пример:
const Person = struct {
    age: u8 = 300,
};

Правило 4. Использование объявленных идентификаторов
Проверяется, что любой тип поля, который не является встроенным типом Zig, объявлен ранее. Это относится и к типам внутри срезов []const T.
Пример:
const Person = struct {
    age: u999,
};

### Структура AST
Описание типов узлов.

| Узел | Назначение | Атрибуты |
|---|---|---|
| `ProgramNode` | Корень дерева, содержит все объявления | — |
| `ConstDeclNode` | Объявление структуры (`const Name = struct { ... };`) | `Name`, `Modifiers` (список модификаторов, например `["const"]`) |
| `FieldNode` | Одно поле структуры | `Name`, `Value` (ссылка на `ValueNode`, может быть `null`) |
| `TypeNode` | Тип поля | `Name`, `IsSlice` (признак среза), `ElementType` |
| `ValueNode` | Значение по умолчанию у поля | `RawValue`, `IsNumeric`, `NumericValue`, `IsBool`, `BoolValue` |

Рисунок CST / AST для верной строки в любом графическом редакторе.
![AST](AST.png)

Формат вывода AST в программе. 
AST выводится в отдельном модальном окне «Дерево AST». Открыть его можно через меню «Текст → Дерево AST» или сочетанием клавиш Ctrl+T.
Формат вывода — текстовое дерево с отступами и символами ├── и └──. Для каждого узла выводятся его тип и атрибуты:
для ConstDeclNode — имя структуры и список модификаторов;
для FieldNode — имя поля и значение по умолчанию (если задано);
для TypeNode — имя типа, либо []const для среза;
для ValueNode — значение.
Пример:
ProgramNode
└── ConstDeclNode: "Person" [const]
    ├── FieldNode: "name"
    │   └── TypeNode: []const
    │       └── TypeNode: "u8"
    └── FieldNode: "age", value: 30
        └── TypeNode: "u8"
